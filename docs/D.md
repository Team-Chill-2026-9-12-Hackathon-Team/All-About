# D evidence engine

`buildAnswer(plan, batch, signal)` consumes C's contract-valid `BrowserBatch`
and returns an `AnswerBundle`. All types come from `@allabout/contracts`.

## Field mapping

- `event_name`, `event_date`/`date`, `event_time`/`time`, `location`/`campus`,
  `organizer`, `registration_link`, `deadline`, `eligibility`, and
  `event_description` go to `summary`.
- `requirements`/`prerequisite` and `submission_format` go to `requirements`.
- extracted student experience goes to `communityNotes`.
- each requested field without a claim produces a scoped `unknowns` entry.

## Evidence rules

Every claim quote must be non-empty and occur in the same snapshot after
whitespace normalization. A title becomes an `event_name` only when the same
title also occurs in snapshot text. Registration links retain the actual URL
captured in text and remove only trailing sentence punctuation.

Real `official` sources receive `institution` authority. Other real pages stay
`unknown`; the engine does not infer instructor identity. Fixture roles can be
provided to `RuleBasedExtractor` through its explicit authority registry.
Only an explicit `instructor` update may supersede an earlier date.

Dates with an offset preserve the offset. Named EST/EDT values retain the name
and map to their explicit offsets. Dates without a year, or times without a
zone, remain `precision: unknown`; they are never confirmed. `fetchedAt` is not
used to resolve policy conflicts.

Deduplication uses field, scope/entity, and normalized value. If `scope.entity`
is absent, the snapshot ID is included so unrelated pages are not merged.
Different activity entities cannot create a date conflict. A source that has
both a snapshot and a failure receives `partial` coverage.
